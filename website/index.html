Physical + digital, one pool

A walk-in and a WhatsApp order should not fight over the same bread.

One stock pool. One order inbox. One Z-report. Whether the sale happens at the counter or in a chat, the ledger sees it the same way.

  • WhatsApp, Instagram, phone, and online orders in one queue.
  • Reserve stock when an order is logged; fulfil and take payment in one step.
  • Cash, M-Pesa, and card land in the same daily total.
  • Pending M-Pesa stays visible until someone confirms it.

No cloud default

No cloud. Just devices.

The counter is the hub. The phone is the remote. They sync when they are on the same Wi-Fi or hotspot. The ledger never needs a server in the middle.

01

Sync when close.

Same Wi-Fi or counter hotspot. No account, no relay, no data plan required.

02

Back up locally.

An encrypted snapshot to a second device, a USB drive, or the merchant's own storage. You are not locked into our cloud.

03

Licence offline.

A signed licence file runs the shop without an internet check. Billing is the only optional online moment.

If two devices edit the same product, price changes are last-writer-wins with an audit trail, stock changes are additive, and payments are immutable. A conflict goes to a human, not a silent overwrite.

The business inbox

Rules that act like an agent. Without the hallucination.

The intelligence layer reads the ledger, diagnoses what changed, and proposes the next move. Every proposal is a typed decision with evidence, assumptions, confidence, and a receipt.

  • Stockout, margin, cash, dead-stock, order, and sales-trend rules.
  • Contribution analysis: “Why did sales drop?” before “What should I do?”
  • Approve, dismiss, or execute through a tool. Mutating tools require human approval.
  • Proactive triggers: sale, order, stock, expense, morning, and a five-minute heartbeat.

The rules do the arithmetic. The model, when we add one, only handles language. No LLM guesses a number.
